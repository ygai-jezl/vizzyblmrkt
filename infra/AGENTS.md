# infra

Setup scripts, one folder per feature. Every script here changes a real Google Cloud project:
it creates secrets, service accounts, IAM bindings, buckets, scheduler jobs, KMS keys or
Firestore settings. Treat each run as a change to someone's live copy. The root `AGENTS.md`
rules apply.

## Before you run anything here

- Ask first, every time. Name the script, the subcommand, the project and what it changes. The
  header of each script lists its subcommands and says which are reversible.
- Most take `<subcommand> <project>`, for example `bash infra/lifecycle/setup.sh verify <project>`.
  With no subcommand they print their help. `verify` (and `validate` in `bigquery-analytics`)
  only read; every other subcommand writes.
- Scheduler subcommands need `APP_URL`, the app's https origin with no path:
  `APP_URL=https://app.example.com bash infra/email-worker/setup.sh scheduler <project>`.
- Prefer `npm run selfhost -- --project <id> --apply <step>`. It does the same work step by step,
  shows the changes and asks first. `docs/self-host.md` maps its steps and add-ons.
- Secret values are generated by the script or typed into the user's own terminal. Never put
  one on a command line or in the chat, and never print one.

## Never

- `infra/x-oauth/setup.sh secret` on a project that already has `social-token-enc-key`. It adds
  a new version of that shared key, so every stored LinkedIn and X token becomes unreadable and
  every connection breaks. For X or LinkedIn app keys use
  `npm run selfhost -- --project <id> --apply addon:x` (or `addon:linkedin`), which leaves the key alone.
- `infra/audit-log/setup.sh lock` without the owner's explicit yes: a locked retention policy
  can't be undone.

## Folders

- `agent`: Vizzy's service account and the role that lets the app call it.
- `audit-log`: the write-once audit log bucket.
- `bigquery-analytics`: Firestore to BigQuery export, datasets and views.
- `billing-killswitch`: a Cloud Function that turns billing off past a budget cap.
- `distribute-worker`, `email-worker`: scheduled jobs that send due posts and emails.
- `github-app`: registers the read-only GitHub App (`create-app.mjs`, has `--dry-run`).
- `invites`: the key that signs invite links.
- `knowledge`: the scraper job's service account and roles.
- `lifecycle`: connected-product keys, the signing key, TTL policies and the journey tick.
- `linkedin-oauth`, `linkedin-cm`, `x-oauth`: social posting app secrets.
